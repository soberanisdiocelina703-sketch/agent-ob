# 未决问题与后续验证



**未决问题：**

0. **全部故障案例均为推演，无内部真实事故样本**。九类故障与三条主线案例（FM-07/08/09）来自竞品资料与公开材料的推演；[R02 自查](R02-方案自查走查记录.md)能发现逻辑漏洞，但受限于本人单一视角与缺少真实样本，无法验证这些故障在真实业务中的发生频率与形态。需向产品负责人获取内部 Agent 现状量级与 1–2 个真实事故形态来校准，这是当前方案最大的外部依赖。相关的悬置分歧（Claude Code 式防线是否说明该类故障不值得诊断）也依赖同一批输入才能定论。
1. 反面证据的真实有效率尚未验证；
2. 版本化聚类签名在真实数据上的同簇率与拆分率尚未验证；
3. 工具打桩回放对幂等键和有状态外部系统的保真度仍需细化；
4. “证据充分 / 有一定依据 / 证据不足”的阈值需用真实复核数据校准，当前仅为交互口径；
5. 待补数据清单尚无持久化回看入口；
6. 多 Agent 链路作为后续扩展，当前数据模型已保留 conversation、root_run 与 parent_run 层级，但本期体验只承诺单 Agent 多步骤；
7. 定价与计费未在本期展开。

**第三周验证项：**

1. 用 10–15 条已知根因 Trace 验证 Top-3 命中率、证据引用完整性和证据等级映射；
2. 招募 3–5 名真实目标用户验证关键路径、状态理解、证据回跳与复核价值；
3. 验证 LangGraph 适配器的层级字段、GenAI 语义属性和 state/handoff/memory 事件；
4. 在 2 个真实开源 Agent 项目验证体检检出率、脱敏隔离策略与误报处理；
5. 用多种运行名称和故障类型检验聚类签名，记录人工合并/拆分成本。
