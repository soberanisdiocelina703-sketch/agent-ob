# 寻迹 UI 设计规范

版本：1.0  
适用范围：`prototype/index.html` 及后续 Web 产品实现

## 1. 设计原则

1. 先给结论和状态，再提供原始 Trace 下钻；
2. 沿用工程后台常见的列表、详情、筛选、对比和确认模式；
3. 颜色只表达品牌、成功、警告、错误、规则和模型来源；
4. 不使用角色扮演式术语，不用动画制造“智能感”；
5. 任何诊断都必须能回到原始事件。

## 2. 字体

### 2.1 字体族

| 场景 | 字体 |
|---|---|
| 中文与界面正文 | `Segoe UI`, `Microsoft YaHei`, `PingFang SC`, sans-serif |
| Trace ID、Span ID、字段值、代码 | `Consolas`, `Courier New`, monospace |

不加载联网字体，保证离线打开时版式稳定。

### 2.2 字号与行高

| Token | 字号 | 行高 | 用途 |
|---|---:|---:|---|
| Display | 30px | 1.2 | 门禁结果、大型状态值 |
| Metric | 26px | 1.2 | 统计卡核心数字 |
| Page title | 20px | 1.35 | Trace 详情标题 |
| Section title | 17px | 1.4 | 页面标题、品牌名称 |
| Card title | 14.5px | 1.5 | 卡片标题 |
| Body | 14px | 1.55 | 默认正文 |
| Control | 13.5px | 1.4 | 按钮、导航 |
| Table | 13px | 1.5 | 表格内容 |
| Small | 12px | 1.5 | 辅助说明 |
| Caption | 11–11.5px | 1.45 | 标签、字段名、时间 |

正文不低于 12px；需要连续阅读的说明不用全大写或高字重。

| `--panel` | `#ffffff` | 卡片与弹窗 |
| `--ink` | `#0f172a` | 主文字 |
| `--ink2` | `#334155` | 次级正文 |
| `--muted` | `#64748b` | 辅助信息 |
| `--line` | `#e2e8f0` | 常规分隔线 |
| `--line2` | `#cbd5e1` | 输入框和按钮边框 |
| `--brand` | `#2563eb` | 主操作、选中态、链接 |
| `--brand-bg` | `#eff6ff` | 选中或定位背景 |
| `--ok` | `#16a34a` | 成功、通过 |
| `--warn` | `#b45309` | 警告、待复核 |

## 4. 间距与圆角

采用 4px 基础栅格。常用间距为 8、10、12、14、16、18、20、24、28px。

| 元素 | 规则 |
|---|---|
| 页面左右留白 | 桌面 28px；窄屏 16px |
| 卡片间距 | 16px |
| 卡片标题内边距 | 13px 18px |
| 卡片正文内边距 | 16px 18px |
| 按钮 | 8px 16px |
| 表格单元格 | 10px 12px |
| 卡片圆角 | 10px |
| 按钮/输入框圆角 | 8px |
| 标签圆角 | 20px |
| 弹窗圆角 | 14px |

## 5. 布局

- 桌面端侧栏宽 216px，主内容区使用剩余宽度；
- 一级导航固定为运行记录、事故、回归与门禁、接入体检、设置；
- 两栏和四栏布局统一使用 16px gap；
- 900px 以下侧栏改为顶部横向导航，所有多栏内容改为单列；
- 运行记录表最小宽度 1040px，事故表最小宽度 980px，其余数据表最小宽度 860px；空间不足时横向滚动，宽屏必须铺满容器。

## 6. 组件

### 6.1 按钮

- 主按钮：品牌蓝实底，每个操作区只保留一个；
- 次按钮：白底灰边；
- 成功按钮：仅用于确认已经核对的结论；
- 危险按钮：白底红边，不用大面积红底；
- 禁用按钮必须说明原因；真实产品若没有该能力，则不展示占位按钮。

### 6.2 标签

标签只用于状态和来源：规则判定、模型推断、通过、警告、失败、待复核、证据等级。标签文字为 11px、半粗体，不用于承载长句。

### 6.3 表格

- 表头 12px、灰色背景、单行显示；
- 每行底部 1px 分隔线；
- 可点击行悬停使用 `--brand-bg`；
- ID 和技术字段使用等宽字体；
- 行数据必须铺满表格宽度，禁止将 `<table>` 改为 block；
- 空结果显示在表格下方，并保留当前筛选条件。

### 6.4 表单与筛选

筛选器高度、边框和圆角一致；标签写在控件内时必须带字段名，例如“执行状态：全部”。搜索输入在输入时过滤，选择器变更后立即过滤，并提供“清除筛选”。

### 6.5 弹窗与反馈

弹窗宽 520px、最大宽度 92vw。提交结果使用页面内状态变化或 2.8 秒 toast；需要补充原因的复核不能直接提交。

## 7. 状态语义

| 维度 | 允许值 | 使用位置 |
|---|---|---|
| 执行状态 | 成功、失败 | 运行记录、Trace 详情 |
| 质量结论 | 通过、不通过、未评估 | 运行记录、基线资格 |
| 事故状态 | 未立案、待复核、已确认、已关闭 | 运行与事故页 |
| 证据等级 | 证据充分、有一定依据、证据不足 | 事故、候选原因、复核 |

任何位置都不能用“成功”同时表达执行和质量。

## 8. 动效

常规动效 150–400ms。证据定位允许 1.6 秒闪烁后保持选中，新用例允许 1.2 秒背景淡出。动画不得阻塞点击，并遵守 `prefers-reduced-motion`。

## 9. 可访问性

- 所有主导航使用真实链接并支持 Enter；
- 非原生可点击元素补 `role=button`、`tabindex=0` 和 Enter/Space 行为；
- 焦点样式为 2px 品牌蓝外框；
- 弹窗使用 `role=dialog` 和 `aria-modal=true`；
- 筛选器必须有 `aria-label`；
- 状态信息同时使用文字与颜色。

## 10. 文案

使用“运行记录、事故、候选原因、证据、复核、回归用例、门禁”等工程团队熟悉的词。避免“庭审、法官、裁决、智能大脑、赋能、抓手”等概念化表达。错误文案必须包含现象、影响和下一步动作。

## 11. 实现对照

| 规范 | 原型位置 |
|---|---|
| 色彩与字体 token | `:root`、`body` |
| 5 个主导航 | `#nav` |
| 全宽数据表 | `.data-table-card` |

| 减弱动效 | `prefers-reduced-motion` |
| 键盘可达 | 脚本末尾的可点击元素增强 |
