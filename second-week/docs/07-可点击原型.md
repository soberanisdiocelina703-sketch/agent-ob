# 任务 7：可点击原型

原型文件：`second-week/prototype/index.html`。单页应用、CSS/JS 分目录管理、离线双击可开。当前版本 **v1.9**（v1.9 为文档口径对齐版本，第二周原型文件本身不改，见 7.5 节）：采用主流工程后台的浅灰背景、白色卡片、左侧导航、无衬线字体与品牌蓝主操作；设计增强集中在首故障点、证据回跳和双向证据复核（见 11.1 节）。

**业务场景：** 「订单助手」单 Agent 客服系统——一个 Agent 按五个步骤执行（规划、订单查询、知识/记忆检索、退款执行、通知）。第二周原型演示的核心事故为 FM-01 状态过期 `INC-2026-0814-003`：用户申请退款 ¥180，退款执行步骤调用退款接口返回 422 失败。**表面报错**在第 9 步退款工具调用；**真实根因**在第 3 步——知识检索步骤读取了 4 小时前的记忆快照 `order_snapshot v3`（状态 PAID、可退 ¥180），而订单真实状态已是 PARTIALLY_REFUNDED（可退 ¥60），过期状态经步骤间传参传给退款执行步骤，导致超额退款请求。

**主线案例的版本差异（见 [00-故障分类与案例事实源.md](00-故障分类与案例事实源.md) 与设计决策 D-09）：** 中期评审后，主线演示案例已从 FM-01 切换为 FM-07 检索排序漂移（`INC-2026-0821-017`）。第二周原型仍演示 FM-01——这是当时的版本状态，作为历史交付不做追溯改写；中期答辩原型（`../../Third-week/midterm/prototype.html`）演示 FM-07 主线，并覆盖九类故障分类。FM-01 在新口径下降级为普通事故，作为「规则可判定类」的对照例保留。

### 7.2 业务操作路径

以下路径对应第二周原型（FM-01 主线，历史交付）；FM-07 主线的操作路径见中期答辩原型。

0. 运行记录 → 筛选「成功」并打开 TRC-9f21 正常详情 → 设为 Diff 基线；
1. 事故列表 → 点簇卡「过期状态污染」筛选定位（簇卡点击用于筛选，不直接替用户进入详情）→ 点开列表中的 INC-2026-0814-003；
2. 诊断工作台 → 先看到规则候选与「语义分析中」加载态（约 1.1s 后模型候选渐入，呈现“规则先行、模型异步”时序，见 8.4 节）→ 症状区 + Top-3 候选 + 因果路径图 → 展开证据抽屉，点击证据引用跳转原始事件（Trace 树驻留高亮）；
3. 成功/失败 Diff → 与成功链 TRC-9f21 对比，状态/传参/工具三维差异；
4. 诊断复核 → 支持证据 4 条证据 vs 反面证据 2 条反证 → 确认是根因（落定动效）；
5. 转回归用例 → 自动生成 REG-1041（含期望不变量，新行高亮滑入）→ 门禁页看运行结果（警告脉冲提示）；
6. 接入体检 → 覆盖率/断链/重复/敏感字段四项报告。

**异常状态（对应任务 6）：** ①体检页断链警告（D-1，含修复指引）；②工作台候选 3 为证据不足的「线索」折叠态、复核入口禁用（G-2）。另有快照过期提示（门禁页 REG-1015）。

### 7.3 关键可操作交互

筛选（簇卡与筛选行）、展开证据（候选抽屉）、证据引用跳原始事件（驻留高亮）、Diff 对比、复核三项结论中选择一项（确认是根因 / 排除该原因并说明理由 / 暂需补充证据并生成清单）、一键转回归用例（字段自动填充）、门禁 Webhook 推送、体检修复指引展开。不可用功能一律显示禁用态并注明原因，不假装可点。
