# 任务 2：Demo 输出（页面设计稿）

本章是任务 7 可点击原型的蓝图：对站点地图（1.3 节）中的 5 个主导航及事故详情的 3 个连续子视图逐一给出设计稿。每份设计稿包含页面目标、区块划分（ASCII 布局）、**第一眼要素**（打开页面 3 秒内必须看到的结论性信息，落实设计原则 1「结论先行」）、主/次操作与页面间数据传递。原型页面与本章一一对应（对照关系见 7.1 节）。示例数据以 [00-故障分类与案例事实源.md](00-故障分类与案例事实源.md) 的 FM-07 主线案例（事故 `INC-2026-0821-017`，失败链 `TRC-7e3d`，基线 `TRC-2b98`）为准。

### 2.0 新增页面：运行记录与正常 Trace 详情

- **页面目标：** 让用户确认正常与异常执行都已被采集，并可查看任意正常 Trace 的完整步骤或把它设为 Diff 基线。
- **第一眼要素：** 近 24 小时运行量、成功率、P95 耗时和事故数；列表默认混合展示成功与失败状态。

```text
┌────────────────────────────────────────────────────────┐
│ [指标] 运行量 1,284 │ 成功率 96.8% │ P95 3.2s │ 事故 12 │
├────────────────────────────────────────────────────────┤
│ [筛选] 状态 │ Agent │ 运行名称 │ Agent版本 │ 时间        │
├────────────────────────────────────────────────────────┤
│ Trace ID │ 状态 │ 时间 │ 运行名称 │ 版本 │ 步骤数 │ 耗时 │ 关联信息 │
└────────────────────────────────────────────────────────┘
                  ↓ 点击成功 Trace
┌────────────────────────────────────────────────────────┐
│ [成功状态 + Trace摘要]                  [设为对比基线]    │
│ [输入输出] [运行摘要]                                      │
│ [完整 Trace树：步骤 / 状态 / 工具结果 / 耗时]               │
└────────────────────────────────────────────────────────┘
```

- **主操作：** 成功 Trace → 打开正常详情；失败 Trace → 进入对应事故。**次操作：** 按状态筛选、将正常 Trace 设为成功/失败 Diff 基线。
- **边界：** 正常 Trace 不生成候选原因，也不进入诊断复核；详情只展示采集事实、性能与输入输出。运行记录是基础浏览入口，事故列表仍是默认落地页。
- **数据传递：** 运行记录向详情传递 `trace_id`；设为基线时向 Diff 页传递 `baseline_trace_id`。

### 2.1 页面① 事故列表（默认落地页）

- **页面目标：** 值班第一屏回答「今天最该先处理哪类失败」。
- **第一眼要素：** 失败模式簇卡按影响排序，最严重簇（红色计数 + 趋势箭头）+ 其最高置信诊断摘要。

```text
┌───────────────────────────────────────────────────────┐
│ [簇卡×4] 检索排序漂移 37会话▲ │ 上下文冲突 11会话 │ 重试状态放大 6会话 │ 过期状态污染 9会话 │
│          每卡：模式名 / 24h次数与趋势 / 影响会话 / 最高置信诊断摘要 │
├───────────────────────────────────────────────────────┤
│ [筛选行] 故障类型 ▾  步骤类型 ▾  步骤名称搜索  时间 ▾  复核状态 ▾  证据等级 ▾ │
├───────────────────────────────────────────────────────┤
│ [事故表] ID │ 时间 │ Agent/运行 │ 症状 │ 首故障步骤(类型/名称) │ 证据等级 │ 复核状态 │
│ [表尾] 历史案例提示：已确认根因 N 条 → 历史案例库用于本簇证据等级加权   │
└───────────────────────────────────────────────────────┘
```

- **主操作：** 点击事故行 → 进入诊断工作台。**次操作：** 点击簇卡 → 筛选列表并定位（根据实际反馈 F-04，簇卡只筛选列表，事故行进入详情）；筛选组合。示例主线为事故 `INC-2026-0821-017`（FM-07 检索排序漂移，首故障步骤 S4 `RETRIEVAL`，症状步骤 S8 `OUTPUT`）；`INC-2026-0814-003`（FM-01 状态过期）作为普通条目保留在列表中。
- **数据传递（→ 工作台）：** `incident_id`、`trace_id`、所属簇 `cluster_id`（用于「同模式历史次数」）、列表中的复核状态（工作台顶部同步显示）。

### 2.2 页面② 诊断工作台（核心页面）

- **页面目标：** 一屏回答「哪一步先出的错、证据是什么、下一步怎么验证」。
- **第一眼要素：** 症状区的报错节点 + 候选根因 1 的一句话结论与证据等级（默认展开）。

```text
┌───────────────────────────────────────────────────────┐
│ [症状条] 症状节点 S8·Judge 0.42 │ 执行全成功(9步·HTTP全200) │ 影响 37会话/14投诉 │ 失败模式 FM-07 │ 数据完整度 92% │
├───────────────────────────────────────────────────────┤
│ [因果路径] S1 → S2 → S3 → ⚑S4(首故障点·检索) → S5 → S6 → ✖S8(症状点)  │
│            节点可点击跳转原始事件；说明行：症状点距首故障点 4 步，全链无报错  │
├───────────────────────────────────────────────────────┤
│ [候选根因 Top-3]（诊断加载态：规则候选先行，模型候选异步追加）        │
│  #1 检索排序漂移(索引重建) [规则+Diff] 证据充分 ─ 展开=证据抽屉(支持4/反证2)+复核入口 │
│  #2 检索未按effective_date过滤 [模型推断] 有一定依据 ─ 展开=证据抽屉        │
│  #3 Judge阈值偏松(折叠)   [模型推断] 证据不足，复核入口禁用(G-2)      │
├───────────────────────────────────────────────────────┤
│ [完整 Trace 树] 默认折叠，标题点击展开；证据跳转在此驻留高亮          │
└───────────────────────────────────────────────────────┘
```

- **主操作：** 展开候选 → 阅读证据 → 「进入诊断复核」。**次操作：** 「成功/失败 Diff」、证据引用跳原始事件、展开 Trace 树、「查看体检」。
- **数据传递（→ Diff）：** `trace_id`（失败链）+ 推荐 `baseline_trace_id` + 候选根因引用的证据锚点（Diff 页据此打「证据」角标）。（→ 复核）：`candidate_id` + 全部证据/反证引用。

### 2.3 页面③ 成功/失败 Diff

- **页面目标：** 回答「和正常的那次差在哪」，把差异直接关联到证据。
- **第一眼要素：** 基线说明（推荐依据三条件）+ 三个维度卡各自的差异数标签（如「状态 Diff · 3 处差异」）。

```text
┌───────────────────────────────────────────────────────┐
│ [基线条] 基线 TRC-2b98（自动推荐：质量通过/同版本/同运行名称/时间邻近）[更换基线]  │
├──────────────────────┬────────────────────────────────┤
│ ① 状态 Diff          │ 失败链列  vs  成功链列（差异行高亮）          │
│ ② 传参 Diff          │ 与候选根因相关的差异行带「证据 E1/E4」角标      │
│ ③ 工具/检索 Diff     │ 反证相关行注明（如「重建前30天top-1稳定为v5 → 候选1反证C2」）│
├──────────────────────┴────────────────────────────────┤
│ [底部] ✓ 差异已确认，进入诊断复核 │ ← 返回诊断工作台               │
└───────────────────────────────────────────────────────┘
```

- **主操作：** 「进入诊断复核」。**次操作：** 更换基线、返回工作台。
- **数据传递（→ 复核）：** 用户在 Diff 页确认过的差异不改变数据，但 Diff 证据（E1/E4）在复核页的支持证据中被引用回跳。

### 2.4 页面④ 诊断复核（设计增强，详见任务 14）

- **页面目标：** 对候选根因做出必选复核，同时对冲 AI 幻觉与自动化偏见。
- **第一眼要素：** 左右分栏的支持证据/反面证据标题与候选结论摘要——用户 3 秒内知道「这里要我做判断，且有反对意见存在」。

```text
┌───────────────────────────────────────────────────────┐
│ [案情条] 候选 1 · 规则+Diff · 证据充分 · 一句话结论                        │
├───────────────────────────┬───────────────────────────┤
│ 🔍 支持证据 · 论证成立          │ 🛡 反面证据 · 反证与替代解释              │
│  1️⃣E1 检索集Diff(排序翻转)  │  ⚡C1 同期23条链召回v3未失败 + 复合条件分析 │
│  2️⃣E2 政策版本Diff  3️⃣E3 索引重建事件 │  ⚡C2 重建前30天top-1稳定为v5 + 分析说明  │
│  4️⃣E4 模型采信链 + 历史案例引用  │  ℹ️ 反面证据声明:未找到其他有效反证        │
├───────────────────────────┴───────────────────────────┤
│ [复核操作区] 复核结论： [确认是根因] [排除该原因] [暂需补充证据]            │
│ 复核后 → 落定态：已复核·转回归用例入口 + 重新复核入口                │
└───────────────────────────────────────────────────────┘
```

- **主操作：** 三项结论中选择一项。**次操作：** 证据引用回跳工作台/Diff、复核后「一键转回归用例」「重新复核」。
- **数据传递（→ 转用例弹窗）：** `incident_id`、复核结论、根因类型（决定不变量模板）、输入摘要、`context_snapshot_ref`、自动反推的 `invariants[]`——弹窗内全部只读自动填充，无需人工字段映射。

### 2.5 页面⑤ 回归集与门禁

- **页面目标：** 让已确认的事故变成发版防线，并回答「这次能不能放行」。
- **第一眼要素：** 门禁结论大字（通过/警告/阻断）+ 通过/警告/阻断计数。

```text
┌───────────────────────────────────────────────────────┐
│ [回归集表] 用例ID │ 来源事故 │ 期望不变量 │ 快照录制 │ 复核状态        │
│            新增用例行高亮（来自转用例流程）                         │
├───────────────────────────────────────────────────────┤
│ [门禁报告] 结论大字:警告 │ 通过11 │ 警告1 │ 阻断0 │ [推送Webhook]    │
│ [明细表] 逐用例结果；不变量违反定位到字段；连续命中提示升级阻断        │
│          + 「调整门禁模式 →」入口        │
└───────────────────────────────────────────────────────┘
```

- **主操作：** 查看警告明细。**次操作：** 推送 Webhook、调整门禁模式（→ 设置页）。
- **数据传递（← 转用例弹窗）：** 新用例对象（含来源 `incident_id`、不变量、录制时间、复核状态=待复核）。

### 2.6 页面⑥ 接入与采集体检

- **页面目标：** 回答「我的数据可不可信」，并把每个问题变成可执行的修复动作。
- **第一眼要素：** 四项体检得分卡，异常项（断链）用警告色边框突出。

```text
┌───────────────────────────────────────────────────────┐
│ [得分卡×4] ①字段覆盖率92% │ ②断链2处⚠ │ ③重复Span14条 │ ④敏感拦截37处 │
├───────────────────────────────────────────────────────┤
│ [问题清单] 问题 │ 位置 │ 影响 │ 修复指引▾（展开=可复制代码片段）      │
│ [表尾] 体检每小时自动运行；得分作为诊断证据等级前置门槛                 │
└───────────────────────────────────────────────────────┘
```

- **主操作：** 展开修复指引。**次操作：** 无（体检自动运行）。
- **数据传递（→ 工作台）：** 数据完整度分数显示在工作台症状区，完整度不足时相关规则禁用并明示「数据不足」（异常 D-3）。

### 2.7 页面⑦ 设置

- **页面目标：** 项目隔离、角色权限、脱敏策略、告警规则、门禁模式的集中管理。
- **第一眼要素：** 成员角色表（谁能复核一目了然）。
- **区块：** 成员与角色（三档：查看者/分析师/复核人）、脱敏策略（规则 + 近 7 天命中数）、告警规则（阈值 + 状态）、门禁模式（警告/阻断切换，注明决策 D-5 建议）。
- **主操作：** 门禁模式切换。**次操作：** 查看脱敏命中、告警阈值。第一期不做成员邀请与 SSO，页面不展示对应入口。
