# 任务 5：PRD——功能、流程、边界

### 5.0 模块与优先级总览

| 模块 | 优先级 | 一句话职责 |
|---|---|---|
| M1 接入与采集体检 | P0 | 数据进得来，且知道数据可不可信 |
| M2A 运行记录与 Trace 详情 | P0 | 正常与异常执行都可查、可下钻 |
| M2 事故列表与失败模式聚类 | P0 | 从海量执行里知道先看哪个 |
| M3 因果诊断工作台 | P0 | 回答「哪一步先出的错、为什么」 |
| M4 成功/失败 Diff | P0 | 回答「和正常的差在哪」 |
| M5 诊断复核（复核与反馈） | P0 | 人拍板，AI 被校准 |
| M6 回归用例与发布门禁 | P1 | 已确认的问题沉淀为防线 |
| M7 设置与权限 | P1 | 项目隔离、脱敏策略、告警规则 |

### M1 接入与采集体检（P0）

- **用户故事：** 作为平台工程师，我想在接入后立刻知道数据是否完整、是否含敏感信息。
- **功能描述：** 提供 OTLP 接入与 LangGraph、OpenAI Agents SDK、Dify 适配器。采集端按项目策略对明确敏感字段做掩码或哈希；服务端二次扫描，命中未授权敏感内容时隔离该载荷并告警，不把受保护原文写入主存储。字段白名单用于避免误伤。
- **输入/输出：** 输入 OTLP 数据流；输出覆盖率、断链、重复、敏感字段四项体检及修复指引。
- **边界：** 不做通用 APM；服务端不自动改写不确定的业务字段，而是隔离并提示管理员处理。
- **验收标准：** AC1-1 5 分钟内出报告；AC1-2 断链、重复和敏感字段均可检出；AC1-3 受保护原文不落主库且有审计记录。

### M2A 运行记录与 Trace 详情（P0）

- **用户故事：** 作为 Agent 开发者，我想查看全部运行，区分“技术上执行完成”和“业务结果正确”。
- **功能描述：** 正常、异常及质量未知 Trace 按时间倒序展示；分别筛选 `execution_status`、`quality_verdict`、运行名称和版本。详情展示输入输出摘要、步骤、耗时与关联事故。仅在质量通过且满足可比条件时允许设为 Diff 基线。
- **边界：** 没有事故的 Trace 不进入诊断与复核，但仍完整可见。
- **验收标准：** AC2A-1 状态组合筛选准确；AC2A-2 正常详情不出现事故诊断区；AC2A-3 技术成功但质量失败的 Trace 可见并可关联事故；AC2A-4 万条 Trace 首屏 ≤ 2s。

### M2 事故列表与失败模式聚类（P0）

- **用户故事：** 作为 SRE，我想先看到影响最大的故障模式，再进入具体事故。
- **功能描述：** 事故按版本化规则签名聚类。`symptom_signature` 描述外显症状，`cause_signature` 在诊断/复核后补充原因维度；签名包含故障类型、归一步骤类型、工具或模型标识、规范化错误码与关键契约字段。故障类型为九类枚举（口径见 [00-故障分类与案例事实源.md](00-故障分类与案例事实源.md)）：`STALE_STATE`、`CONTRACT`、`TOOL_CALL`、`RETRIEVAL_EMPTY`、`MODEL_OUTPUT`、`ORCHESTRATION`、`RETRIEVAL_DRIFT`、`CONTEXT_CONFLICT`、`RETRY_AMPLIFICATION`。列表筛选故障类型、步骤类型、步骤名称、时间、复核状态和证据等级。支持人工合并、拆分并保留历史。
- **边界：** 第一期不自动做语义聚类；单簇展示最近 500 条。
- **验收标准：** AC2-1 已知模式同簇率目标 ≥ 80%；AC2-2 首屏 ≤ 2s；AC2-3 筛选可组合；AC2-4 签名升级可追溯；AC2-5 故障类型筛选覆盖全部九类枚举，任一类型的事故均可正确归类与检索（枚举归类属数据口径，全部九类适用；类型的自动判定能力另见 M3 阶段标注）。

### M3 因果诊断工作台（P0）

- **用户故事：** 作为 Agent Owner，我想在一屏内看到最早异常、证据与验证动作。
- **功能描述：** 工作台包含症状、Top-3 候选原因、因果路径和证据抽屉。候选显示“证据充分 / 有一定依据 / 证据不足”，不展示未经真实数据校准的百分比。内部原始评分仅用于排序和离线校准；每条结论必须引用可回跳的原始事件并给出反面证据或明确说明未找到。诊断覆盖九类故障，判定路径按能力阶段区分（见 00 事实源 0.2 节）：FM-02 `CONTRACT`、FM-03 `TOOL_CALL`、FM-04 `RETRIEVAL_EMPTY` 为 **T1 已实现**；FM-05 `MODEL_OUTPUT` 为 T1 部分实现（规则部分已实现，模型语义部分设计中）；FM-01 `STALE_STATE`、FM-06 `ORCHESTRATION`、FM-07 `RETRIEVAL_DRIFT`、FM-08 `CONTEXT_CONFLICT`、FM-09 `RETRY_AMPLIFICATION` 为 **T2 设计中**，不作为已实现能力验收。
- **边界：** 不自动修复、不自动定责；证据不足的候选仅作线索且不能进入正式复核；候选最多 3 条。
- **验收标准：** AC3-1 Top-3 命中率目标 ≥ 70%（按 00 事实源 0.7 节分桶统计：规则可判定类 ≥ 90%、语义复合类 FM-07/08/09 ≥ 60%、混合类 ≥ 70%；语义复合类属 T2，本期仅预置验收基准不实测）；AC3-2 上屏候选 100% 有有效引用；AC3-3 首屏规则结果 ≤ 3s，异步结果可增量到达；AC3-4 T1 已实现类型（FM-02/03/04）的判定可用标注事故集实测，T2 设计中类型不得在界面或报告中标注为已实现。

### M4 成功/失败 Diff（P0）

- **用户故事：** 作为开发，我想把失败执行与真正可比的质量通过执行放在一起查看差异。
- **功能描述：** 自动推荐基线必须同时满足：质量通过、同 Agent 与版本、同运行名称，并通过输入语义、工具/模型版本、关键数据版本及实验配置兼容性检查；时间邻近只用于排序。页面展示状态、传参与工具三个维度 Diff，并公开推荐依据。
- **边界：** 无合格基线时明确提示；用户手选不兼容基线需显式确认；大字段只对比哈希与摘要。
- **验收标准：** AC4-1 兼容性规则 100% 执行并展示；AC4-2 已知差异 100% 检出；AC4-3 页面 ≤ 3s。

### M5 诊断复核：复核与反馈（P0）

- **用户故事：** 作为资深工程师，我不想被 AI 的一面之词带偏；我想同时看到「为什么成立」和「为什么可能不成立」，然后自己拍板。
- **功能描述：** 对选中的候选根因，左右分栏呈现——支持证据（事实 + 论证逻辑）与反面证据（系统强制生成的反证与替代解释）。底部复核区三个必选按钮：**确认是根因 / 排除该原因 / 暂需补充证据**。复核后：「确认是根因」→ 引导转回归用例；「排除该原因」→ 要求选择理由（证据错误 / 因果不成立 / 另有根因）并可指认正确根因；「暂需补充证据」→ 生成待补数据清单（缺哪类事件）。所有复核写入校准日志，作为诊断器的反馈信号。支持重新复核（保留复核历史，见任务 6 异常 U-1）。
- **输入/输出：** 输入候选根因 ID；输出复核记录（结论 + 理由 + 复核人 + 时间）。
- **边界：** 复核不可跳过——未复核的事故不能转回归用例（见任务 12 决策 D-3）；复核权限仅限项目成员中的「复核人」角色。
- **验收标准：** AC5-1 每次复核必须落库且可查历史；AC5-2 反面证据区 100% 有内容（找不到实质反证时明确显示「未找到有效反证」而不是空白）；AC5-3 重新复核后旧复核保留且校准信号同步更新。
- **详细设计见任务 14（双向证据复核）。**

### M6 回归用例与发布门禁（P1）

- **用户故事：** 作为 Agent Owner，我想让每个修过的事故变成发版前的自动检查，同样的坑不踩第二次。
- **功能描述：** 「成立」复核后一键转回归用例：自动打包输入、上下文快照（脱敏后）、期望不变量（从根因反推，如「refund_amount ≤ refundable_amount」）。用例归入回归集。新版本发布前运行回归集，输出门禁报告：通过 / 警告 / 阻断。默认只警告不阻断，团队可按回归集配置为阻断（依据见任务 12 决策 D-5）。
- **输入/输出：** 输入已复核事故；输出回归用例（快照 + 不变量）与门禁报告。
- **边界：** 不做完整 CI/CD（持续集成/交付）系统，只提供 CLI（命令行）与 Webhook（网络钩子）供现有流水线调用；快照回放第一期只支持「工具打桩回放」（用录制的工具返回值），不做真实外部调用重放。
- **验收标准：** AC6-1 转用例操作 ≤ 2 步且字段自动填充；AC6-2 注入已知回归后门禁能报警；AC6-3 门禁结果可通过 Webhook 推送。

### M7 设置与权限（P1）

- **用户故事：** 作为平台管理员，我要隔离不同业务的项目数据、控制谁能复核、配置脱敏规则。
- **功能描述：** 项目级隔离；角色三档：查看者（只读）、分析师（可诊断、不可复核）、复核人（可复核与重新复核）；脱敏策略（字段白名单 + 正则规则，采集端优先执行，第一周 11.4 节）；告警规则（按失败模式簇的次数/比例阈值）。
- **边界：** 第一期不做 SSO（单点登录）与审计导出；不做跨项目数据共享。
- **验收标准：** AC7-1 三档角色权限边界经测试用例逐条验证；AC7-2 脱敏规则生效后原文不落库（抽样审计验证）。
