# 寻迹：Agent 链路诊断产品设计

本目录是第二周任务的完整提交包。评分时从本文件开始；所有文档、原型和图片均使用相对路径，解压后不需要安装依赖或启动服务。

## 快速检查路径

1. 打开[设计总览](design/overview.html)，了解问题、核心流程和技术方案；
2. 双击[可点击原型](prototype/index.html)，依次检查“运行记录 → 事故列表 → 诊断 → 复核 → 回归门禁”；
3. 按下表检查 `docs/` 中的 14 项任务，一项对应一个文件；
4. 查看[原型状态说明](prototype/状态说明.md)和[UI 设计规范](design/UI设计规范.md)；
5. 最后核对[三人走查原始记录](research/11-原始记录/索引.md)、[实际项目评审记录](research/R01-项目评审反馈.md)、[方案自查走查记录](research/R02-方案自查走查记录.md)及[尚待验证的问题](research/待验证问题.md)。

## 提交范围

寻迹面向需要排查 Agent 运行问题的研发、测试和平台团队。产品同时展示正常、异常和质量未评估的 Trace；异常运行可继续进入首故障点定位、证据复核、成功链路对比、回归用例和发布门禁。

本期交付的是可离线运行的高保真前端原型，不连接生产数据库。原型内采用固定业务样本来保证交互路径稳定；这些样本用于呈现字段、状态和操作逻辑，不作为线上业务指标或用户测试结果。验证证据分三类、分开记录：实际收到的项目评审反馈（R01）；同事A、同事B 和产品经理C 三名真实用户完成的走查测试；本人对方案做的对抗式自查（R02，非他人评审，其方法边界在该文件中写明）。

## 离线打开

完整压缩 `second-week` 目录并发送。对方解压后双击 `prototype/index.html` 即可操作原型，双击 `design/overview.html` 可查看设计总览。不要单独发送 HTML 文件，否则相对路径引用的 CSS、JavaScript 和图片会丢失。
