# 原型状态与触发说明

本文用于评分和验收时快速复现界面状态。原型是单页应用，入口为 [index.html](index.html)，页面切换不会发起网络请求。

## 四种基础状态

| 状态 | 界面表现 | 当前原型中的触发方式 | 产品实现要求 |
|---|---|---|---|
| 默认态 | 展示列表、指标和可执行操作 | 打开 `index.html`；左侧导航切换模块 | 首屏先显示页面骨架，再填充最新数据；筛选条件需保留 |
| 加载态 | 工作台先出现规则候选，语义候选显示“分析中” | 从事故列表打开 `INC-2026-0814-003`，进入诊断工作台 | 规则结果与模型结果分阶段返回；加载中不锁死已有信息 |
| 空状态 | 给出空的原因、当前筛选和恢复动作 | 在列表筛选中选择无法命中记录的组合 | 不能只显示空白；提供“清空筛选”或返回上一级入口 |
| 错误态 | 错误原因、影响范围和重试/修复入口同时出现 | 打开“接入体检”，查看断链、重复事件或敏感字段项 | 保留已成功加载的数据；重试只作用于失败模块 |

## 业务异常态

| 异常态 | 复现路径 | 预期反馈 |
|---|---|---|
| 证据不足 | 事故详情 → 诊断工作台 → 展开第三个候选 | 候选标记为“线索”，复核入口禁用，并列出待补证据 |
| Trace 断链 | 接入体检 → 查看断链检查项 | 展示缺失的父子跨度、影响 Trace 数和接入修复建议 |
| 快照过期 | 回归集与门禁 → 查看 `REG-1015` | 标明快照版本和过期原因，不把它算作有效门禁结论 |
| 复核冲突 | 两个评审者对同一诊断提交不同结论 | 后提交者收到版本冲突提示，刷新后重新确认，不覆盖先前结果 |
| 门禁警告 | 事故详情转为回归用例并完成复核 | 新用例加入门禁列表，警告数更新，Webhook 操作返回明确结果 |

## 关键交互复现

1. 在“运行记录”选择成功记录，可查看正常 Trace，并设为 Diff 基线；
2. 在“事故列表”点击事故簇只改变筛选，不直接跳过列表；
3. 打开事故后展开证据，点击引用会回到 Trace 原始事件并保持高亮；
4. 在“诊断复核”选择结论后，可将已确认问题转为回归用例；
5. 新用例必须先完成复核，之后才进入门禁运行。

## 尚未接入的真实环境状态

静态原型不连接鉴权、后端接口和持久化存储，因此刷新后会恢复初始状态。接口超时、真实权限不足和跨会话并发冲突的详细处理规则见[任务 6](../docs/06-异常流程.md)与[任务 8](../docs/08-技术方案.md)。
