## 6.2 关键问题修复：FB-04 聚合多样性（V1 → V2）

### 复现与根因

V1 命中实录（真实录制回放；修复前的原始记录保留在 DEMO.md §5 的 V1 附注中）：

```
bad-tool-args 候选池（按分数排序）：
  1.10 rule reconcile (exception)        ← Top-1
  1.05 rule reconcile (tool_arg)         ← Top-2
  1.05 rule reconcile (contract)         ← Top-3  ┐ 三席全被同一步骤占据
  1.05 rule write_report (contract)               │
  0.85 diff fetch_payments  ← 指向注入点，排第 5 ┘ 未上屏
```

根因：`aggregate()` 纯按分数截断 Top-3，无 span/来源多样性约束——多规则同时命中
一个下游步骤时，系统性掩盖上游源头（docs/05 问题 3）。

### 修复内容（server/xunji/diagnosis.py `_select_diverse`）

1. **同一 first_fault_span 至多 2 席**（`MAX_PER_SPAN`）；
2. **rule / diff 各保底一席**（若池中存在）：保底者从队尾挤掉「其来源已占多席」的
   最低分候选，各来源只剩一席时保底不成立（不挤掉某来源的唯一代表）。

### 对 docs/05 原提案的设计修正（迭代中的迭代）

docs/05 问题 3 原提案为「异构来源（rule/diff/**model**）至少各保留一席」。实现时用
真实候选池验证发现：Top-3 下三来源全保底会把确定性候选压到 1 席，且让低置信的
model 兜底解释(0.35)挤掉字段级证据卡（`tool_arg_violation: payments[4].amount`）——
医治了「源头被掩盖」却制造「强证据被弱证据挤出」。**V2 修正为 model 不参与保底、
只补空位**（冷启动/规则沉默场景下自然上位，见 stale-source rank2）。
已回写 docs/05 反哺清单第 2 条口径。
