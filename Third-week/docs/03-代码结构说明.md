## 3.2 关键流程走读：一条失败 Trace 的旅程

1. `agent/run_agent.py` 起 `claude -p`（stdin 喂提示词），`sdk/cli.py cmd_run` 逐行消费
   stream-json → `parser.StreamParser` 重建 Span 树（tool_use/tool_result 配对、
   工具信封提取 step_name/input/output/quality、截断流闭合为 error）；
2. `POST /v1/traces` → `ingestion.ingest`：必填缺失丢弃并警告、断链标记 broken_parent、
   载荷落 payloads 表（对象存储替身）；
3. `pipeline.process_trace` → `incidents.detect_incident`：最后失败步骤为症状，
   `clustering.assign_cluster` 按签名建/归簇；
4. `diagnosis.run_sync_diagnosis`（同步，毫秒级）：`causal.build_graph` →
   `rules.evaluate_rules`（异常传播取**最早**失败步骤——报错≠根因的代码化）→
   `diffgen`（选兼容成功基线，首分歧生成候选）→ `aggregate`（无证据丢弃、
   同 span+cause 去重合并证据、同分早步骤优先、Top-3）→ 状态 partial 先渲染；
5. `run_model_stage`（异步线程，30s 超时）：Evaluator 产出候选+反证，
   `validate_model_output` 强制证据引用存在，失败只记 failure_reason 不阻塞 → complete；
6. 前端复核（If-Match 版本控制）→ `gate.create_regression_case`（confirmed 才允许，
   打包 no_recurrence + quality_pass 不变量）→ `gate.run_gate` 对 release 全部运行
   重放规则与不变量 → pass/warn/block。
