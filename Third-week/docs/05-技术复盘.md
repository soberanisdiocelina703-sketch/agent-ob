# 任务 6：技术复盘

每条问题统一结构：**设计原文 → 实现事实 → 定性 → 影响 → 建议修改 → 优先级**。
「设计问题」与「本周简化导致」严格分开（后者见 §C）。

## A. 设计问题（需反哺产品方案）

### 问题 1：核心语义数据不是行业通用约定（本周最大发现，已形成正式裁定）

- **设计原文**：docs/08 §8.3 events_state/handoff/memory 三表及 §8.4 状态过期规则；docs/03 五层机制以状态级因果为主叙事。
- **实现事实**：OTel GenAI 语义约定只覆盖模型/工具调用级 Span；「状态」「交接」是 LangGraph/OpenAI Agents SDK 的框架原生概念，Claude Code 通用事件流中不存在，无法自动采集。
- **定性**：不可行（在通用接入前提下）。
- **影响**：差异化主张（状态级因果回溯）在浅接入用户身上无法兑现，宣传与能力脱节会击穿信任。
- **建议修改**：docs/03 §3.3 五层机制、docs/04 差异化——按 T1/T2 分级重写：第一期承诺 T1 证据 + Diff 对照定位；状态级因果标注为「深接入/状态原生框架增强」。docs/08 §8.3 三表标注 T2。
- **优先级**：P0（反哺清单第一条）。

### 问题 2：LLM 文本漂移使 Diff 产生伪根因

- **设计原文**：docs/08 Diff 设计未区分步骤类型，隐含「逐步骤全量对比」。
- **实现事实**：真实录制中 assistant 文本每次运行必然不同，Diff 把 llm_call 步骤判为「首分歧」（伪根因，真实数据实证，见 retro 2026-08-21）。
- **定性**：缺失。
- **建议修改**：docs/08 §8.2 diff 接口契约增补「对照仅含 tool_call/retrieval/validation 步骤；语言步骤展示但不参与分歧判定」。
- **优先级**：P1。

### 问题 3：聚合排序会把异构候选挤出 Top-3（bad-tool-args 未命中的直接原因）

- **设计原文**：docs/08 §8.4 聚合器「合并去重、证据加权排序、Top-3 截断」。
- **实现事实**：三条规则候选（同指 reconcile）分数均高于 Diff 候选（指向真正源头 fetch_payments），Top-3 全被单一步骤占据；注入点步骤未上屏（命中实录 2/3，见 DEMO.md §5）。
- **定性**：设计不完整（排序未考虑来源/位置多样性）。
- **影响**：Top-3 命中率直接受损；多规则同时命中一个下游步骤时系统性掩盖上游源头。
- **建议修改**：docs/08 §8.4 聚合规则增补：「同一 first_fault_span 至多占两席；异构来源（rule/diff/model）至少各保留一席（若存在）」。
- **优先级**：P1（直接影响北极星指标）。

### 问题 4：门禁评估范围未定义

- **设计原文**：docs/08 §8.2 gate-run 仅说「返回 pass/warn/block 及逐用例结果」。
- **实现事实**：E2E 实测「只评估 release 最新一次运行」会漏掉更早运行中的复现（最新一条恰好是另一故障类型时门禁误放行）。
- **定性**：口径含糊。
- **建议修改**：docs/05 门禁模块验收标准锁定「评估该 release 的全部运行（可配窗口/上限），任一违例即不过」。
- **优先级**：P1。

### 问题 5：接入的平台差异与权限形态完全缺位

- **设计原文**：docs/05 接入与采集体检模块（完整度/断链/重复/敏感字段）。
- **实现事实**：真实接入连环踩坑——Windows 下 claude 是 .CMD 垫片（多行 prompt 走 argv 被折断）；嵌套会话终端工具名是 PowerShell 而非 Bash（授权规则随平台变化）；headless 权限墙拦截后 Agent 真实改变策略（连拒 4 次后改用 Read 翻文件，已存档 fixtures/raw/permission-denied-sample.jsonl）。
- **定性**：缺失。
- **影响**：接入首日体验决定产品生死；权限被拒产生的「假失败 Trace」还会污染基线池与聚类。
- **建议修改**：docs/05 体检模块增补「平台矩阵检测 + 权限配置探测 + 权限拒绝事件独立分类（不计入故障统计）」；接入文档增加平台差异章节。
- **优先级**：P1。

### 问题 6：枚举与并发控制载体多处未锁定

- **设计原文**：docs/08 有 evidence_grade/incident_status 字段无取值；failure_type 「单独定义」但未定义；If-Match 未指明比对载体；regression_cases.suite_id 引用了未定义的 suites 表。
- **实现事实**：全部由本期实现单方面锁定（enums.py、candidates.version、补建 suites 表）。
- **定性**：口径含糊 / 缺失。
- **建议修改**：docs/08 §8.3 按 docs/02 §2.3 对照表逐项锁定；补 suites 表定义。
- **优先级**：P2（实现已定，回写文档即可）。

### 问题 7：冷启动价值曲线未写进产品叙事

- **设计原文**：docs/03 价值主张直接从「自动定位首故障点」讲起。
- **实现事实**：无基线时 Diff 降级、静默故障只剩「证据不足」态；本期靠 `correct_cause_ref` 人工指认兜底闭环 + checkup 的 baseline_coverage 提示（两者皆为实现中新增）。
- **定性**：叙事缺失。
- **建议修改**：docs/03 §3.5 增补「接入首日 → 一周」价值阶梯：证据组织与资产沉淀先兑现，自动定位随基线积累启用；docs/06 冷启动分支引用 baseline_coverage。
- **优先级**：P1。
