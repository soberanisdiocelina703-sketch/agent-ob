# 任务 08｜AI 能力拆解：竞品用了什么 AI、效果如何、我们如何做得更好

## 1. 分析口径

链路产品中的 AI 能力分为四类：

1. **理解数据**：总结 Trace、解析输入输出、自然语言查询。
2. **发现问题**：异常检测、聚类、告警降噪。
3. **判断质量**：LLM-as-a-Judge、轨迹和工具调用评估。
4. **推动行动**：根因候选、修复建议、创建查询/告警/数据集。

## 2. 阿里云 AI 能力

### 公开能力

- 智能告警：覆盖模型、工具、Token、Agent 调用等维度。
- 告警异常分析与根因定位。
- LoongSuite Pilot 的 alarm-triage 可基于异常快照并行分析根因，生成结构化问题记录和修复建议。
- AgentLoop 评估、实验和数据集处理会消耗 AI 积分，说明平台使用模型完成自动化分析/评估。
- Agentic 接入通过 Skill + CLI，由 Agent 理解自然语言接入需求并自动编排命令。

### 使用的 AI 形态推测

- 大模型：对异常上下文、日志和 Trace 做摘要、根因候选和建议生成。
- Agent/Tool Calling：调用 CMS CLI、查询日志/指标、编排接入或分析步骤。
- 规则与统计：异常检测、错误率/耗时阈值、同环比和分位数。
- RAG：可能检索产品文档、历史案例或告警知识，但公开文档未完整披露具体实现。

### 效果判断

优点：能结合阿里云底层数据，行动范围大；自然语言接入确实降低复杂配置门槛。

待验证：AI 根因的准确率、证据展示、置信度、误报率和反馈校准机制公开信息有限。

## 3. 华为云 AI 能力

### 公开能力

- 轨迹质量评估器：用 LLM 判断 Agent 内部轨迹是否逻辑连贯、持续推进并完成目标。
- 工具参数正确性：检查参数完整性、类型和幻觉参数。
- 任务完成度、幻觉、参考答案遵从度等预置评估器。
- 在线评估：从生产 Trace 按时间、采样等规则自动拉取并评估。
- 智能分析报告：调用大模型总结评估结果，并支持人工校准评分。

### 使用的 AI 形态

- 大模型 Judge：按 Rubric 对输出或轨迹评分并解释。
- 规则/结构校验：工具参数类型、必填字段和确定性条件。
- 数据回流：将生产 Trace 转成评测输入，形成线上到线下闭环。
- 人在回路：人工校准覆盖模型原始评分，用于修正统计结果。

### 效果判断

优点：AI 评估目标明确，且具备人工校准；轨迹级评估比只评最终答案更适合 Agent。

风险：LLM Judge 对 Rubric、模型、上下文长度敏感；如果 Trace 字段缺失，评估可能把采集问题误当成 Agent 问题。

## 4. Langfuse AI 能力

### 公开能力

- LLM-as-a-Judge：预置幻觉、相关性、毒性、有用性等评估器，也可自定义。
- 支持线上 Observation 抽样评估和离线实验评估。
- Code Evaluator：执行 Python/TypeScript 逻辑，适合 JSON、schema、regex 和工具调用检查。
- Langfuse Assistant：自然语言查询 Trace、Observation、Session、成本和指标，并在确认后创建筛选、数据集或配置。
- Judge 自身执行也生成 Trace，可以排查 Judge Prompt、模型响应和 Token 成本。

### 使用的 AI 形态

- 多模型 LLM Judge。
- Agent + MCP/Tool 调用实现自然语言数据探索和动作。
- 规则/代码评估器处理确定性问题。
- 人工标注、用户反馈与模型评分统一存为 Score。

### 效果判断

优点：AI 能力开放、可追踪、可抽样并能与实验闭环；确定性检查与 LLM 判断分工清楚。

风险：不同 Judge 的一致性和费用需要自行校准；Assistant 当前公开信息显示自托管版不可用。

## 5. 横向对比

| 能力 | 阿里云 | 华为云 | Langfuse |
|---|---|---|---|
| 异常/告警分析 | 强，结合云底座 | 以观测指标和评测为主 | 依赖 Dashboard/Monitor 与外部规则 |
| 根因候选 | 已公开智能分析/分诊 | 可从 Trace 和报告分析 | Assistant 可探索数据，但基础设施根因需外部系统 |
| 轨迹质量评估 | AgentLoop 评估体系 | 强，预置轨迹/工具评估器 | 强，自定义 Judge + Code Eval |
| 自然语言操作 | Agentic 接入 | 智能分析报告 | Assistant + MCP/工具 |
| 人工校准 | 公开资料不突出 | 明确支持 | Annotation/Score/Feedback 完整 |
| AI 执行可观测 | 待实机验证 | 报告与评分可查 | Judge 执行本身有 Trace |

## 6. 我们可做得更好的方向

### 方向一：确定性算法先行

关键路径、墙钟贡献、重试、排队和断链检测应由确定性算法完成。大模型负责解释和排序，不负责发明时间关系。

### 方向二：证据化根因

每个 AI 根因候选固定输出：

```text
候选原因
├─ 支持证据
├─ 反证/尚未排除项
├─ 与正常基线的差异
├─ 置信度及原因
└─ 下一步可执行查询
```

### 方向三：采集健康度作为 AI 前置条件

AI 分析前先检查：断链、时钟偏差、必填属性、采样、输入输出缺失。数据不完整时降低置信度或只给补采集建议。

### 方向四：按成本自适应

- 规则先筛选高影响 Trace。
- 小模型做摘要和分类。
- 高价值/高不确定样本再调用强模型。
- 提供项目级 AI 分析预算和采样上限。

### 方向五：反馈闭环

用户可标记“根因正确/错误”“建议有效/无效”，反馈进入评测集；每个版本公布 Top-1/Top-3 命中和误导率，而非只展示 Demo。

## 7. AI 效果指标

| 能力 | 核心指标 |
|---|---|
| Trace 摘要 | 事实准确率、关键信息覆盖、节省阅读时间 |
| 异常聚类 | 簇纯度、告警压缩比、代表样本覆盖 |
| 根因候选 | Top-1/Top-3 命中、误导率、专家一致性 |
| LLM Judge | 与人工一致率、分场景校准、成本/样本 |
| 自然语言查询 | 查询一次成功率、越权率、平均减少步骤 |
| 修复建议 | 采纳率、首次修复成功率、回归率 |
