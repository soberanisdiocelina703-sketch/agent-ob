01 竞品扫描

三家竞品，三条路线。

同样做 Agent 链路，打法完全不同。

阿里云 AgentLoop

云上全栈运维
五种 Trace 视图、全局拓扑、告警与底层资源联动。

  • 强：Agent 语义 + 云全栈
  • 弱：视图多，依赖排障经验

华为云 AgentArts

观测到评测
Session 下钻 Trace，问题样本回流成评测集。

  • 强：观测与评测闭环
  • 弱：数据分属三个产品

Langfuse

开放数据平台
MIT 开源、OTel 原生、跨模型跨框架。

  • 强：开放、可自托管
  • 弱：自托管运维成本高

共同点

Session → Trace → Span 层级OpenTelemetry 接入gen_ai.* 语义字段总览 → 筛选 → 下钻AI 正从总结走向行动

会议中的“Longlongfuse”按语境校正为 Langfuse。

05 设计逻辑

页面结构，是底座决定的。

不是审美差异，而是数据模型、目标用户与商业底座的结果。

阿里为何五视图

一条 Trace 同时存在层级、依赖、时间、语义、统计五类问题，而用户既有开发者也有 SRE。

华为为何强调 Session

体验发生在多轮会话里，而生产 Trace 本身就是最真实的评测数据。

Langfuse 为何 Observation-first

Agent 链路越来越深，统一事件模型让观测与评测共享同一数据原子。

我们继承什么，改变什么

继承

  • 清晰的 Session / Trace / Span 层级
  • OTel 兼容与自动采集
  • 跨页面保持上下文

改变

  • 先选问题，不先选视图
  • 默认算墙钟关键路径
  • 自动匹配正常基线
  • 采集完整度作为一等信息
  • AI 结论必须带证据

08 AI 能力

都在用 AI，都没解决可信。

能力阿里云华为云Langfuse
告警根因分析强一般依赖外部
轨迹质量评估有强强
自然语言操作接入编排分析报告Assistant
人工校准不突出支持完整

我们的做法

算法先行

关键路径、重试、排队由确定性算法算出。大模型负责解释和排序，不负责发明时间关系。

数据不全就不下结论

断链、时钟偏差、字段缺失先检查；不完整时只给补采集建议。

每条 AI 结论的固定结构

1根因候选
2支持证据
3反证与未知
4置信度
5下一步动作

10 差异化

不是画出链路，
是解释等待。

竞品让用户看见一条 Trace；我们直接告诉他为什么等，以及下一步做什么。

七个差异点

P0 · 墙钟关键路径

算出真正影响完成时间的路径，不把并行分支简单相加。

P0 · 采集健康度

断链、时钟偏差、字段缺失显性化，决定所有结论的可信度。

问题导向入口

首屏只有四个选项：慢、错、贵、不准。

等待语义化

把空白时间分成排队、首 Token、网络、重试退避、串行化等类型。

自动正常基线

同版本同意图的成功请求自动调出来做对照。

证据化 AI

每条结论都带证据、反证、置信度与下一步。

用户等待时间线

提交 → 排队 → 首 Token → 完成，与工程 Span 对齐。

差异带来的变化

现在的结论

“这个 Span 花了 14 分钟。”

我们的结论

“正常同类请求 1.8 秒。本次因 3 次 504 重试达到 14 分钟，占关键路径 70%。”

11 缺陷

九个缺口，两个必须先补。

级别竞品的缺口首期动作
P0采集问题被当成业务问题完整度与字段检查
P0展示耗时但不解释关键路径关键路径与等待分类
P1正常基线要用户自己找自动匹配相似成功 Trace
P1AI 根因没有可验证证据固定证据/反证/置信度结构
P1敏感输入输出治理不突出采集端脱敏与分级权限
P2跨产品计费算不清统一成本估算与预算
P2开发态与生产态割裂统一环境与版本模型
P2多视图造成选择负担问题导向入口
P2自托管“免费”隐藏运维成本轻量模式与规模计算器

值得改的不是页面更漂亮，而是让诊断少依赖专家经验、让数据缺失不再隐形。

Go

Pivot

No-Go

14 战略预判

半年后，画出链路只是及格线。

六个趋势

OTel 语义收敛

字段标准化，兼容性成为竞争点。

树变成图

跨 Trace Link、异步、Agent 委派成为一等对象。

观测与评测融合

问题 Trace 一键进回归集。

Copilot 走向动作

不只总结，还能建查询、数据集与告警。

采集双轨

语义埋点管高层，eBPF 补运行时。

治理成为购买条件

脱敏、保留期、RBAC、成本可预估。

我们的半年路线

阶段目标
第 1 月做透慢请求：关键路径、等待分类、采集健康
第 2 月证明优于普通 Trace 浏览：基线与差异视图
第 3 月生产可用：采样、脱敏、RBAC、告警
第 4 月扩展异常与成本归因
第 5 月连接会话与质量
第 6 月形成 AI 闭环与修复验证

最佳切入不是追齐所有模块，而是把“用户等待 → 关键路径 → 证据根因 → 修复验证”做到明显更快、更可信。
