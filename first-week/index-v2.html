为什么第一个是长耗时

最痛

用户转圈 20 分钟，没人能解释——这是最强的未被满足需求。

最频

每天都在发生，不是偶发故障，有持续优化空间。

可做

只需时间、关系、状态三类数据，无需内容理解，合规风险最低。

差距最大

三家竞品都没有关键路径算法，这是最大的白地。

评分为研究假设，需用户访谈校准。访谈计划已就绪，真实访谈尚未开始。

05 设计逻辑

页面结构，是底座决定的。

不是审美差异，而是数据模型、目标用户与商业底座的结果。

阿里为何五视图

一条 Trace 同时存在层级、依赖、时间、语义、统计五类问题，用户既有开发者也有 SRE，五视图是被迫的覆盖。

华为为何强调 Session

体验发生在多轮会话里，而生产 Trace 本身是最真实的评测数据，Session 是连接两者的枢纽。

Langfuse 为何 Observation-first

Agent 链路越来越深，统一事件模型让观测与评测共享同一数据原子，降低两套系统的接入成本。

我们继承什么，改变什么

✅ 继承

  • 清晰的 Session / Trace / Span 层级
  • OpenTelemetry 兼容与自动采集
  • 跨页面保持上下文
  • GenAI 语义属性（gen_ai.*）

🔄 改变

  • 先选问题，不先选视图
  • 默认算墙钟关键路径
  • 自动匹配正常基线
  • 采集完整度作为一等信息
  • AI 结论必须带证据与置信度

核心转变：从"让用户读数据"到"直接给用户结论 + 证据"。

三个核心技术难点

⚡ 异步与多 Agent

父子关系无法表达因果（消息队列/跨服务委派）。
路径：使用 Span Link；区分调度与执行时间。

🌊 流式输出

duration 表达不了用户感知（首 Token 到末 Token 差异大）。
路径：记录 first_token / last_token 时间戳事件。

🕐 时钟偏差

多服务时间线错位，甚至出现负耗时。
路径：Collector 校时 + 偏差估计 + 显性告警。

14 战略预判

半年后，画出链路只是及格线。

六个行业趋势

📐 OTel 语义收敛

字段加速标准化，兼容性成为竞争点。首期应基于 OTel 扩展而非造私有协议。

🕸 树变成图

跨 Trace Link、异步、Agent 委派成为一等对象。图算法要从首期就设计进去。

🔄 观测与评测融合

问题 Trace 一键进回归集。即使首期聚焦性能，也应留接口给后续评测。

🤖 Copilot 走向行动

不只总结，还能建查询、数据集与告警规则。AI 能力要从解释向执行演进。

📡 采集双轨

语义埋点管高层语义，eBPF 补运行时细节。两条采集路径将共存。

🔒 治理成为购买条件

脱敏、保留期、RBAC、成本可预估。中大型企业不购买治理能力不到位的产品。
