# 任务 06｜商业模式分析：竞品如何变现

> 价格依据 2026-08-07 可见官方页面，采购前需重新核价。

## 1. 阿里云 AgentLoop

### 收费结构

AgentLoop 采用按量后付费、按天出账：

| 计费项 | 目录价 | 主要用途 |
|---|---:|---|
| AI 积分 | 0.01 元/积分 | 评估、实验、数据集向量化等模型消耗 |
| 数据集存储 | 0.00004 元/条/天 | AgentLoop 数据集 |
| 执行次数 | 0.001 元/次 | 评估、实验等样本执行 |

关联产品另行计费：

- Agent 可观测依赖 ARMS，按 ARMS 计费。
- 审计和评测/实验结果依赖 SLS。
- 资产管理依赖 MSE，公开文档显示相关模块仍可能处于公测阶段。

### 变现逻辑

1. 观测能力带动 ARMS Trace 与指标数据消费。
2. 审计和结果数据带动 SLS 存储与查询消费。
3. 评估、实验、智能分析通过 AI 积分获得增值收入。
4. 与阿里云 AI、微服务和基础设施绑定，提高客户迁移成本。

### 优点与风险

优点：按量起步，适合从试用扩展；云上联动价值明显。

风险：跨 AgentLoop、ARMS、SLS 的账单不直观，客户难以提前计算端到端成本。

## 2. 华为云 AgentArts

### 收费结构

观测界面本身不收费，但数据进入不同底层服务：

| 数据 | 底层服务 | 方式 |
|---|---|---|
| Trace | APM | 按上报数据量等规则计费 |
| Metric | AOM | 按数据量/用量计费 |
| Log | LTS | 按采集、存储、查询等规则计费 |

评估模块还可能产生模型调用和任务执行成本，具体取决于套餐与评估方式。

### 变现逻辑

1. AgentArts 以开发、发布、观测、评测一体化留住 Agent 工作负载。
2. 观测数据带动 APM/AOM/LTS 的用量收入。
3. 在线评估和智能分析带动模型与平台使用。
4. 平台原生 Agent 自动上报，降低使用底层云服务的门槛。

### 优点与风险

优点：观测界面低门槛，用户按实际数据用量支付。

风险：三类数据分开计费，使用者需要理解多个产品；高并发 Trace 可能产生意外费用。

## 3. Langfuse

### 收费结构

#### 开源自托管

- 核心功能采用 MIT 许可，可免费自托管。
- 用户自行承担计算、ClickHouse、PostgreSQL、Redis、对象存储、备份、升级和运维成本。
- 自托管 Enterprise 提供高级安全、RBAC、审计、保留策略和支持，定制报价。

#### Langfuse Cloud

Cloud 以 units 计量：

```text
Units = Trace 数 + Observation 数 + Score 数
```

公开套餐示例：

| 套餐 | 基础价格 | 包含量/特征 |
|---|---:|---|
| Hobby | 免费 | 约 50k units/月、30 天数据访问、2 用户 |
| Core | 29 美元/月 | 约 100k units；超额约 8 美元/100k；90 天 |
| Pro | 199 美元/月 | 更高吞吐、3 年数据访问、高级功能 |
| Enterprise | 2499 美元/月起 | 定制吞吐、企业支持、安全与合规 |

### 变现逻辑

1. OSS 免费获取开发者与生态。
2. Cloud 出售“免运维”和弹性扩展。
3. 数据保留、吞吐、SSO/RBAC、审计、合规和支持构成企业增值。
4. 不按席位收费，鼓励跨团队协作；按使用量随客户业务增长。

### 优点与风险

优点：定价与 Trace/Observation 使用量直接关联；OSS 降低锁定顾虑。

风险：深层 Agent 每条 Trace 含大量 Observation，单位数增长可能比请求数快；自托管的真实成本容易被“许可证免费”掩盖。

## 4. 商业模式对比

| 维度 | 阿里云 | 华为云 | Langfuse |
|---|---|---|---|
| 主要收入 | 云可观测用量 + AI 增值 | APM/AOM/LTS 用量 + 平台/评估 | SaaS units + 企业版/支持 |
| 免费策略 | 新用户额度、公测模块 | 界面免费、底层数据收费 | OSS 免费 + Cloud Hobby |
| 锁定方式 | 云产品和基础设施联动 | AgentArts 全生命周期与华为云底座 | 数据/API 开放，靠产品体验和托管便利 |
| 成本风险 | 跨产品账单复杂 | 三类数据分别计费 | 深 Trace units 增长、自托管运维 |

## 5. 对我们的建议

### 推荐计费单位

首期可采用“有效 Observation/Span 数据量 + 保留期”作为基础计费，AI 诊断或评估单独按执行量/Token 计费。

### 必须提供

- 接入前成本估算器。
- 采样和保留策略模拟。
- 每 Agent/项目/团队预算与告警。
- AI 分析费用上限与抽样比例。
- 不完整/丢弃数据不计费或透明展示。

### 避免

- 按请求数但不考虑深层 Observation，导致成本与资源不匹配。
- 把 Trace、Log、Metric 价格完全割裂却不提供总成本视图。
- 让 AI 诊断默认全量执行，造成不可控模型费用。
