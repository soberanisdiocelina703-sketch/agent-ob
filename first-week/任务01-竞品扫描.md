# 任务 01｜竞品扫描：3 个链路追踪竞品基本信息

> 研究日期：2026-08-07。本任务聚焦 Agent 链路管理，会议中的“Longlongfuse”按语境校正为 **Langfuse**。

## 1. 竞品选择

| 竞品 | 产品定位 | 产品形态 | 选择理由 |
|---|---|---|---|
| 阿里云 AgentLoop / 云监控 2.0 AI Agent 可观测 | Agent 观测、评估、实验和审计平台；观测部分承接原 ARMS LLM 应用监控 | 公有云商业产品 | 国内云厂商中链路视图和云底座联动较完整，2026-07-30 刚完成产品升级 |
| 华为云 AgentArts | 覆盖智能体开发、部署、运营运维与评测；观测模块统一管理原生和第三方 Agent | 公有云商业产品 | 代表“Trace → 标注 → 数据回流 → 在线/离线评测”的闭环路线 |
| Langfuse | 开源 AI Engineering 平台，覆盖 Trace、Session、Prompt、评测、数据集和实验 | 开源自托管 + SaaS | 开源、中立、跨模型/跨框架，适合作为我们验证产品能力的开源基线 |

## 2. 阿里云基本信息

### 核心能力

- Agent、LLM、Tool、MCP、Memory、Chain、Retriever、Embedding 等 Span 追踪。
- Trace 列表、卡片和轨迹视图。
- 单 Trace 提供调用树、链路图、时序线、推理轨迹、链路分析等视图。
- 会话回放、Token/模型/工具/Skill 场景化分析。
- 全局拓扑、健康度、告警与日志/事件/微服务联动。
- Python/Go 探针、OTel、Dify 内置 OTel，以及通过 Skill 自动编排接入。

### 目标用户

Agent 应用开发者、AI 平台团队、SRE/运维、需要统一管理多个 AI 应用的企业客户。

### 一句话评价

优势是“Agent 语义 + 云上全栈运维”，不足是页面和视图较多，用户仍需较强排障经验。

## 3. 华为云基本信息

### 核心能力

- 智能体概览、业务指标和运营指标。
- 会话分析以及 Session → Trace 下钻。
- 调用树、Span 输入输出、错误、元数据、指标、日志和标注。
- 第三方 Agent 通过 OpenTelemetry/OTLP 上报 Trace 与 Metric。
- Trace 筛选、人工标注、回流评测集。
- 轨迹质量、工具参数正确性、幻觉、任务完成度等评估器。
- 大模型生成评估结果智能分析报告，支持人工校准。

### 目标用户

AgentArts 平台开发者、使用华为云 MaaS/智能体平台的企业、AI 运营和质量评估团队。

### 一句话评价

优势是观测和评测闭环；不足是 Trace、Metric、Log 分属 APM/AOM/LTS，且目前运营运维仅统计 API 调用数据。

## 4. Langfuse 基本信息

### 核心能力

- Trace、Observation、Session、User、Token 和成本追踪。
- Python/JS SDK、OpenTelemetry、框架集成、LiteLLM 和 API 接入。
- Agent Graph、Trace Log、Tool Call 展示。
- Prompt 管理、数据集、实验、人工标注与用户反馈。
- LLM-as-a-Judge、代码评估器、Dashboard 和 Metrics API。
- MIT 开源自托管与 Langfuse Cloud。

### 目标用户

需要跨模型/跨云观测的 AI 工程团队、初创公司、希望私有化部署的企业和开源开发者。

### 一句话评价

优势是开放、跨框架和 AI Engineering 闭环；不足是自托管生产架构包含 PostgreSQL、ClickHouse、Redis、对象存储等组件，运维成本不低。

## 5. 扫描结论

三家形成三种竞争路线：

1. **阿里：云上全栈运维路线**——强调多视图、拓扑、告警和底层资源联动。
2. **华为：观测到评测路线**——强调生产 Trace 沉淀为评测资产。
3. **Langfuse：开放数据平台路线**——强调标准协议、自托管和跨框架工程闭环。

我们的产品不应只复制 Trace 列表，而应在“自动关键路径、等待原因解释、正常基线对比、采集可信度”上建立差异。
