# 任务 02｜功能拆解：阿里云 AgentLoop 链路追踪核心流程

## 1. 拆解对象

选择阿里云 AgentLoop / 云监控 2.0“AI Agent 可观测”的链路追踪模块。选择原因：其 Trace 表达方式最完整，且同时覆盖 Agent 语义、会话和传统云可观测联动。

## 2. 核心用户任务

> 当 Agent 请求变慢、失败、成本异常或输出有问题时，从整体异常逐步定位到具体 Span，并获得继续排查所需的输入输出和运行上下文。

## 3. 端到端功能流程

### 步骤 1：数据接入

用户先创建云监控工作空间，通过以下方式接入：

- Python 框架：自动探针/`aliyun-bootstrap`。
- Go 框架：Go 探针/`instgo`。
- Dify 等平台：内置 OpenTelemetry。
- 自定义应用：OTel 和自定义埋点。
- Agentic 接入：AI Agent 调用 CMS Skill/CLI 自动识别框架并编排接入命令。

接入价值：把不同框架的执行过程统一为 Agent、LLM、Tool、MCP、Memory、Retriever 等 Span。

### 步骤 2：全局发现

用户从总览或 Agent 实体页查看：

- 活跃会话、对话、Agent 数。
- Trace 数、平均耗时、Token 消耗。
- 模型和工具的调用、错误、耗时。
- Agent、模型、工具等实体之间的全局拓扑与健康状态。

这一步回答：“问题影响多大、集中在哪类对象？”

### 步骤 3：搜索与聚合 Trace

链路追踪页支持查询表达式、筛选和按维度聚合。Trace 列表包含：

- Trace ID、开始时间和端到端耗时。
- 输入、输出。
- Total Tokens。
- 应用名、用户 ID、会话 ID。

用户通过时间、错误、应用、Agent、用户或会话缩小范围。

### 步骤 4：进入 Trace 详情

顶部信息栏先展示：

- Trace ID、会话 ID、用户 ID。
- 总耗时、总 Token。
- Agent 数、LLM 调用次数、工具调用次数。
- 请求输入与最终输出摘要。

用户先判断该 Trace 是否与当前问题相关，再进入结构分析。

### 步骤 5：在五种视图中分析

| 视图 | 解决的问题 | 主要信息 |
|---|---|---|
| 调用树 | 调用层级是什么？ | Span 类型、名称、属性、耗时甘特条 |
| 链路图 | 节点如何依赖？ | 拓扑、调用数、状态、耗时；轨迹/聚合切换 |
| 时序线 | 时间具体花在哪里？ | 瀑布图、Span 详情、Input/Output、资源、事件和 Link |
| 推理轨迹 | Agent 看到了什么、做了什么？ | System/User/Assistant/Tool 消息流 |
| 链路分析 | 本条链路的性能与调用统计如何？ | 总耗时、Token、LLM/Tool/Skill 调用等聚合 |

### 步骤 6：联动继续排障

在 Span 详情中可以进一步：

- 查询关联日志。
- 查看事件。
- 跳转微服务可观测链路。
- 用资源属性定位服务、主机、实例、SDK 等来源。

这一步把 Agent 层问题连接到底层应用和基础设施。

### 步骤 7：聚合治理

在场景化分析页按 Token、模型、工具和 Skill 聚合：

- 模型 TTFT、平均耗时、P90/P99、错误类型。
- 工具调用次数、错误、平均/P90/最大耗时。
- Token 在模型、应用和 Agent 间的分布。
- 告警与智能分析。

## 4. 功能结构图

```text
接入
  ↓
总览 / 拓扑 / Agent 实体
  ↓
Trace 搜索、聚合、趋势
  ↓
Trace 顶部摘要
  ↓
调用树 ─ 链路图 ─ 时序线 ─ 推理轨迹 ─ 链路分析
  ↓
Span 输入输出 / 属性 / 资源 / 事件 / Link
  ↓
日志、事件、微服务联动
  ↓
场景分析、告警、长期治理
```

## 5. 流程优点

- 从全局到局部逐级下钻，符合 SRE/开发者排障习惯。
- 同一 Trace 同时提供结构、时间、拓扑和语义视角。
- Agent 专属语义与传统 APM 底座连接。
- 能从 Session 进入 Trace，也能从 Agent 实体进入相关 Trace。

## 6. 流程问题

- 五种视图的选择成本高，新用户不清楚先看哪一个。
- 展示了大量数据，但“关键路径”和“下一步排查动作”仍依赖人工判断。
- 复杂链路中 duration 最大的 Span 不一定是墙钟关键路径，容易误判。
- 观测、评测、日志等跨产品计费，用户难以预估总体成本。

## 7. 对我们的启示

首屏不应要求用户先选视图，而应先选择问题类型：慢、错、贵、不准。系统随后自动组合关键路径、Span 证据、基线对比和日志联动。
