# 任务 11｜缺陷挖掘：竞品未做好的点与改进方案

## 1. 缺陷一：多视图造成选择负担

### 表现

阿里提供调用树、链路图、时序线、推理轨迹和链路分析；完整但新用户需要先理解每种视图。

### 根因

产品以数据表达方式组织，而不是以用户问题组织。

### 改进

- 提供慢/错/贵/不准的问题入口。
- 系统根据问题自动推荐主视图。
- 视图切换保持同一 Span 与时间焦点。

## 2. 缺陷二：展示耗时但不解释关键路径

### 表现

竞品普遍展示瀑布图和 duration，但并行 Agent 中最大 duration 不一定是端到端瓶颈。

### 根因

传统 APM 主要按 Span 展示，没有把 Agent 的并行、循环和重试转成墙钟贡献。

### 改进

- 自动计算关键路径。
- 区分墙钟时间和累计工作量。
- 显示边际贡献、并行空洞和本可并行的串行步骤。

## 3. 缺陷三：缺少自动正常基线

### 表现

用户需要自己筛选相似正常 Trace，比较模型、工具、参数和时间。

### 根因

Trace 浏览器关注单次执行，未把“相似请求匹配”作为核心能力。

### 改进

- 按意图、版本、模型、工具集合、输入规模匹配基线。
- 固定展示调用次数、Token、参数、时序和资源差异。
- 明确告诉用户基线为何相似。

## 4. 缺陷四：AI 根因缺少可验证证据

### 表现

部分产品宣传智能分析或根因定位，但公开页面对置信度、反证、评价指标和反馈闭环描述不足。

### 风险

大模型可能把相关性写成因果关系，用户因流畅文本而过度信任。

### 改进

- 所有结论附原始 Trace/Log/Metric 证据。
- 输出反证和未知项。
- 显示置信度来源。
- 收集用户确认并发布离线准确率。

## 5. 缺陷五：采集问题被误当成业务问题

### 表现

华为第三方接入要求严格 `gen_ai.*` 字段；缺少资源属性可能导致界面查询失败。其他平台也可能存在断链、属性缺失和时钟偏差。

### 根因

观测产品默认假设 Trace 数据完整。

### 改进

- 独立的采集健康页面。
- 字段映射检查和修复建议。
- Trace 完整度、孤儿 Span、时间不守恒检测。
- 数据不完整时限制 AI 结论。

## 6. 缺陷六：开发态与生产态割裂

### 表现

华为文档明确说明，目前仅 API 调用进入运营运维统计，控制台调试和编排预览不计入。

### 影响

开发者无法用同一观测体验比较调试、灰度和生产；问题样本在环境间流转困难。

### 改进

- 用 environment/version/release 区分数据而非完全分开。
- 支持从调试 Trace 一键生成测试用例。
- 灰度/生产采用同一对比视图和字段契约。

## 7. 缺陷七：自托管“免费”隐藏运维成本

### 表现

Langfuse OSS 免费，但生产依赖 Web/Worker、PostgreSQL、ClickHouse、Redis、对象存储。

### 影响

小团队低估容量、升级、备份、合并和高可用成本。

### 改进

- 提供单机轻量模式和生产规模计算器。
- 明确事件量、对象存储、ClickHouse 和保留期的资源估算。
- 将采样、归档、冷热分层配置产品化。

## 8. 缺陷八：跨产品计费复杂

### 表现

阿里 Agent 可观测依赖 ARMS，其他结果依赖 SLS；华为 Trace/Metric/Log 分别进入 APM/AOM/LTS。

### 影响

客户难以预估一个 Agent 的完整月成本。

### 改进

- 统一总成本看板。
- 接入前模拟日请求量、平均 Span、保留期和 AI 分析比例。
- 每项目预算、异常费用告警和一键降采样。

## 9. 缺陷九：敏感输入输出治理不突出

### 表现

Agent Trace 可能保存系统 Prompt、用户数据、工具参数、数据库结果、文件 URI 和多模态内容。

### 风险

全量保存会带来隐私、商业机密、权限和合规风险。

### 改进

- 采集端字段级脱敏。
- 内容与元数据分级权限。
- 按项目/字段配置保留期。
- 导出和查看原文的审计记录。
- 默认只加载摘要，原文按需、按权限读取。

## 10. 缺陷优先级

| 优先级 | 缺陷 | 首期动作 |
|---:|---|---|
| P0 | 采集不可信 | 完整度与字段检查 |
| P0 | 不解释关键路径 | 关键路径与等待分类 |
| P1 | 缺少基线 | 自动相似正常 Trace |
| P1 | AI 无证据 | 固定证据/反证/置信度结构 |
| P1 | 敏感数据 | 采集端脱敏与权限 |
| P2 | 计费复杂 | 成本估算和预算 |
| P2 | 开发/生产割裂 | 统一环境和版本模型 |

## 11. 结论

真正值得改进的不是页面是否更漂亮，而是让诊断更少依赖专家经验、让数据缺失不再隐形、让 AI 结论可验证、让总体成本和数据风险可控。
