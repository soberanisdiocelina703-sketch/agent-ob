# 任务 14｜战略预判：竞品未来半年迭代方向

> 时间范围：2026-08 至 2027-02。以下内容基于三家近期官方产品变化做出的推断，不代表厂商承诺。

## 1. 判断依据

- 阿里在 2026-07-30 将 ARMS LLM 应用监控升级为云监控 2.0 AI Agent 可观测，新增全局拓扑、多视图 Trace、会话、场景大盘和智能告警。
- 华为在 2026 年持续完善 AgentArts 第三方 OTel 接入、会话、Trace 回流、在线评估和轨迹评估器。
- Langfuse v4 在 2026 年转向 OTel/Observation-first 数据模型，并强化 Agent Graph、Evaluator 和 Assistant。

## 2. 趋势一：OpenTelemetry 与 GenAI 语义进一步收敛

### 证据

三家都支持或转向 OTel，华为和阿里明确使用 `gen_ai.*` 属性，Langfuse v4 以 OTel 为主要摄取方式。

### 半年预判

- 更多 Agent 框架实现开箱即用自动采集。
- LLM、Tool、Retriever、MCP、Agent、Memory 的字段逐步标准化。
- 厂商会提供字段映射检查、版本兼容矩阵和接入健康诊断。
- OpenTelemetry GenAI 语义版本变化会成为产品兼容竞争点。

### 对我们的意义

数据模型应以 OTel 为基础，扩展字段必须命名空间化，避免形成不可迁移的私有协议。

## 3. 趋势二：Trace 从树扩展为复杂 Agent Graph

### 证据

阿里已有链路图、聚合图、推理轨迹和 Link；Langfuse Agent Graph 关注循环、多步工具；多 Agent 和 MCP 快速发展。

### 半年预判

- 跨 Trace Link、异步任务、消息队列和 Agent 委派会成为一等对象。
- UI 会加入循环折叠、重复步骤聚合、子 Agent 泳道和因果链。
- 单纯父子树无法满足复杂 Agent，图和日志串联视图会继续增强。

### 对我们的意义

首期就应保留 Link 数据模型，并将墙钟关键路径设计为图算法，不要只支持树。

## 4. 趋势三：观测与评测加速融合

### 证据

华为已支持 Trace 回流、在线评估和轨迹质量评估；Langfuse 把线上 Observation、数据集、实验和 LLM Judge 连接；AgentLoop 包含评估与实验。

### 半年预判

- 低分、错误、高耗时 Trace 可一键加入回归集。
- 线上评估会增加按风险、版本、用户或问题簇的智能采样。
- 评测对象从最终回答扩展到工具选择、参数、轨迹效率和安全。
- 性能、成本、质量三个维度会在同一版本对比中出现。

### 对我们的意义

即使首期聚焦性能，也应允许把问题 Trace 保存为基线/回归样本，为后续评测留接口。

## 5. 趋势四：AI Copilot 从总结走向可执行动作

### 证据

阿里已有 Agentic 接入和告警分诊；Langfuse Assistant 能查询数据并创建筛选、数据集或配置；华为能生成智能评估报告。

### 半年预判

- 自然语言生成 Trace 查询、过滤条件和指标图。
- 自动聚类告警并生成问题单。
- 基于 Trace 创建数据集、评估器或告警规则。
- 修复建议会关联代码、Prompt、工具配置和版本实验。
- 高风险操作继续采用人类确认，而非完全自动执行。

### 对我们的意义

Copilot 的差异不在聊天框，而在能否带着权限和上下文调用诊断工具，并给出可验证、可回滚的动作。

## 6. 趋势五：采集方式形成“语义埋点 + 运行时观测”双轨

### 证据

阿里同时出现 OTel/探针、Hook 和 eBPF；华为第三方使用 OTel；AI Coding Agent 等场景存在无法修改源码的需求。

### 半年预判

- OTel/SDK 继续负责 Prompt、Tool、Agent 等高层语义。
- eBPF/Hook/代理负责进程、网络、文件和未纳管 Agent 活动。
- 平台会尝试把两类数据按进程、会话和时间关联。
- “零侵入”会成为营销重点，但语义完整度仍依赖应用/框架数据。

### 对我们的意义

不能把 eBPF 当成语义采集替代品；产品应明确数据来源和可信范围。

## 7. 趋势六：成本、安全与数据治理成为核心购买条件

### 证据

三家都记录 Prompt、Output、Token、用户和工具数据；Langfuse 套餐强调保留期、RBAC、审计与合规；云厂商按数据用量计费。

### 半年预判

- 字段级脱敏、保留期、区域、RBAC 和审计进一步产品化。
- Token 成本与观测平台自身数据成本会统一展示。
- 企业客户要求 BYOC/私有化/专有网络链路。
- 采样策略将从固定比例升级为按风险、版本和异常自适应。

### 对我们的意义

数据治理和成本估算必须从首期架构考虑，不能等功能做完后补。

## 8. 三家竞品具体预判

### 阿里云

1. 加强 AI Coding Agent、MCP、Skill、Runtime/eBPF 的采集覆盖。
2. 把智能告警、分诊与根因建议更深地连接 SLS/ARMS/微服务。
3. 强化云监控 2.0 统一实体和拓扑。
4. AgentLoop 的观测、评估、实验、审计之间形成更多跳转和数据复用。

### 华为云

1. 完善第三方 OTel Agent 的字段兼容和统一视图。
2. 增加更多轨迹、工具、RAG 和安全类评估器。
3. 缩短 Trace 回流与在线评估路径。
4. 改善开发/调试与生产运营数据割裂。

### Langfuse

1. 推进 v4 全面切换与旧 SDK/API 迁移。
2. 强化 Observation-first 查询、深 Agent Trace 性能和 Graph。
3. 扩展 Evaluator、Monitor、Metrics API 和 Assistant 动作能力。
4. 在自托管版本补齐 v4 稳定性、升级和企业部署工具。

## 9. 我们未来半年建议路线

| 阶段 | 目标 | 重点能力 |
|---|---|---|
| 第 1 月 | 做透慢请求 | 关键路径、等待分类、采集健康 |
| 第 2 月 | 证明优于普通 Trace 浏览 | 正常基线、差异视图、日志/指标联动 |
| 第 3 月 | 生产可用 | 采样、脱敏、RBAC、告警、容量 |
| 第 4 月 | 扩展异常与成本 | 问题聚类、错误传播、Token/成本归因 |
| 第 5 月 | 连接会话与质量 | Session、问题 Trace 回归集、用户反馈 |
| 第 6 月 | 形成 AI 闭环 | 证据化 Copilot、在线评估、修复验证 |

## 10. 战略判断

半年后，“能展示 Trace”将成为基础能力，真正的竞争点会转向：

1. 是否能覆盖复杂、多 Agent、异步链路。
2. 是否能自动把数据变成可信诊断与行动。
3. 是否能把线上问题沉淀为评测和回归资产。
4. 是否能控制数据成本、敏感信息和企业权限。
5. 是否开放、可迁移并兼容主流 OTel 生态。

我们的最佳切入方式不是追齐所有竞品模块，而是先把“用户等待 → 关键路径 → 证据根因 → 修复验证”做到明显更快、更可信。
