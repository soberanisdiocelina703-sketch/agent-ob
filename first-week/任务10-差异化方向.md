# 任务 10｜差异化方向明确：针对优先场景的突破点

## 1. 目标场景

长耗时 Agent 请求的性能瓶颈定位。

## 2. 差异化定位

> 竞品帮助用户“看见一条 Trace”；我们帮助用户“用证据解释用户为什么等待，并立即知道下一步行动”。

## 3. 差异点一：问题导向入口

### 竞品常见方式

用户先进入 Trace 列表，再决定用树、图、时序线或推理轨迹。

### 我们的方案

首屏按问题分类：

- 慢：关键路径、等待类型、基线差异。
- 错：错误传播、重试、最后成功节点、日志。
- 贵：Token/成本归因、重复调用、上下文膨胀。
- 不准：检索/Prompt/工具/输出轨迹和评测。

系统自动编排最适合的视图，专家仍可进入原始 Trace。

## 4. 差异点二：自动墙钟关键路径

### 竞品常见方式

显示每个 Span 的 duration，由用户阅读瀑布图。

### 我们的方案

- 计算真正影响端到端完成时间的关键路径。
- 不把并行分支 duration 简单相加。
- 显示每个节点对墙钟时间的边际贡献。
- 区分“累计工作量”和“用户实际等待”。

价值：减少对超大 Trace 的人工阅读和误判。

## 5. 差异点三：等待状态语义化

将“空白时间”分为：

- 模型排队。
- 首 Token 等待。
- 工具网络/服务端等待。
- 重试退避。
- 人工审批等待。
- 本地计算。
- 本可并行却串行执行。
- 采集缺失或时钟偏差。

价值：同样是 10 秒，不同等待类型对应完全不同的优化动作。

## 6. 差异点四：自动正常基线

为异常 Trace 自动匹配：

- 同 Agent 和意图/Trace 名。
- 同版本、环境、模型和工具集合。
- 相似输入规模和 Token。
- 状态成功且耗时位于正常分位。

差异视图只突出：模型/工具版本、参数、调用次数、Token、错误、时序和资源差异。

价值：把“这个 Span 14 分钟”升级为“正常同类请求 1.8 秒，本次因 3 次 504 重试达到 14 分钟”。

## 7. 差异点五：证据化 AI 诊断

每条 AI 建议包括：

| 字段 | 示例 |
|---|---|
| 根因候选 | Tool 服务超时触发指数退避 |
| 支持证据 | 连续 3 次 504；关键路径贡献 70% |
| 正常基线 | 同版本同工具仅调用 1 次，P50 1.8 秒 |
| 反证/未知 | 缺少工具服务端 CPU 指标 |
| 置信度 | 0.86，高；Trace 完整度 97% |
| 下一步 | 打开工具日志；检查超时与重试上限 |

价值：让 AI 结论可检查、可反驳、可执行。

## 8. 差异点六：采集可信度

在 Trace 顶部显示：

- 关键 Span 类型覆盖率。
- 断链和孤儿 Span。
- 客户端/服务端时钟偏差。
- 必填 GenAI 字段缺失。
- 采样/丢弃情况。
- 输入输出是否被脱敏或截断。

只有完整度达到阈值时才给高置信根因。

## 9. 差异点七：用户等待与工程执行统一

单独显示用户可感知阶段：

```text
提交 → 排队 → 首次进展 → 首 Token → 流式输出 → 完成
```

并与 Agent/LLM/Tool Span 对齐。这样产品和工程可以讨论同一条时间线。

## 10. 差异化优先级

| 优先级 | 能力 | 原因 |
|---:|---|---|
| P0 | 关键路径 + 等待类型 | 最直接解决“为什么等” |
| P0 | 采集健康度 | 决定所有诊断可信度 |
| P1 | 正常基线对比 | 显著减少人工判断 |
| P1 | 用户等待时间线 | 连接产品体验和工程数据 |
| P1 | 证据化 AI 候选 | 放大诊断效率但需要 P0 数据 |
| P2 | 问题 Trace 回归集 | 从排障扩展到持续改进 |

## 11. 不作为差异点的能力

- 再做一套普通 Trace 列表。
- 单纯增加更多图表或颜色。
- 没有证据的“AI 一键根因”。
- 仅支持单一 Agent 框架的漂亮 Demo。
- 把传统 APM 字段换成 LLM/Tool 名称。

## 12. 验证方法

使用同一批“慢工具、模型重试、上下文膨胀、串行化、采集缺失”Trace，对比竞品和我们的：

- 找到正确瓶颈的时间。
- 点击数。
- Top-1 判断正确率。
- 用户对下一步行动的确定性。
- 新手与专家差距。
